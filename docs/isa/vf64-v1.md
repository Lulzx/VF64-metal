# VF64 virtual ISA version 1.0

VF64 is a source-language-independent, data-parallel instruction format for
virtual binary64 execution. The normative opcode and layout table is
[`vf64-v1.json`](vf64-v1.json). Unknown versions, opcodes, feature bits,
reserved control bits, and out-of-range registers or slots are invalid programs.

## Binary format

Programs are little-endian arrays of 32-bit words. The eight-word header is:

```text
magic  version  instruction_count  register_count
input_slots  output_slots  lane_count  feature_bits
```

`magic` is `0x56463634` (`VF64`), version is `0x00010000`, register count is
1–32, and v1 feature bits are zero. `lane_count` is the exact vector length;
dispatch with any other length is invalid.

Every instruction is eight words:

```text
opcode  dst  src0  src1  src2  control  immediate_low  immediate_high
```

The control word contains rounding in bits 0–2, `exact` in bit 3, and precision
mode in bits 8–9. All other bits are zero. The 64-bit constant operand is
`immediate_high:immediate_low`; load/store use `immediate_low` as the slot.

## Vector execution and storage

Each virtual register is a vector of `lane_count` raw 64-bit slots. A Metal
invocation executes one lane per GPU thread. Arithmetic, comparison,
conversion, select, move, and constant instructions are therefore vector
operations. `lane_u64` produces the zero-based lane index. Inputs and outputs
are slot-major arrays indexed as `slot * lane_count + lane`. `load`, `store`,
and the final flags write are observable packed boundaries.

Registers are untyped raw slots. Floating values use IEEE binary64 interchange
bits; comparisons use zero or one; integer conversions use low 32/64-bit
two's-complement or unsigned encodings; binary16/32 use their low 16/32 bits.

## Numerical modes

- Mode 0, `ieee64`, uses the complete M2 runtime, all five rounding modes,
  sticky exception flags, and true fused FMA.
- Mode 1, `fast48`, uses the frozen pair contract. Arithmetic requires
  nearest-even and does not raise IEEE flags.
- Mode 2, `wide48`, uses the frozen scaled-pair contract. Arithmetic requires
  nearest-even and does not raise IEEE flags; FMA is multiply then add.

Mode is consumed by arithmetic opcodes. Comparison, conversion, remainder, and
round-to-integer instructions operate on the packed register value with M2
semantics. This makes every semantic operation available without silently
claiming reduced arithmetic is IEEE-correct.

Flags are sticky per lane. `flags_clear` resets them and `flags_get` copies the
mask to a raw register. Program completion also writes one `uint` mask per lane.

## Control and termination

Execution is straight-line in v1. `nop` has no effect; `halt` ends the lane.
Programs without `halt` end after `instruction_count`. `select` chooses `src1`
when raw `src0` is nonzero and `src2` otherwise. No instruction may observe
uninitialized registers: the validator rejects such a program.

V1 intentionally has no branches, calls, atomics, transcendentals, or hidden
fallbacks. New behavior requires a version or declared feature bit.

## Standalone Metal backend

The backend consumes binary program and slot-major input files and writes raw
output and per-lane flag files:

```bash
.build/release/f64-metal vf64-run program.bin input.bin output.bin flags.bin
```

All files use the little-endian layouts above. The runner validates the entire
program, including definite register initialization, before dispatching
`vf64_interpreter_kernel`. No source-language frontend participates in this
path.
