# Publication-time FP64 prior-art audit

Search date: 2026-08-29  
Status: source-inspected landscape snapshot; not proof of universal novelty

## Question

The proposed 1.0 claim combines four properties:

1. correctly rounded IEEE-754 binary64 on Apple GPUs;
2. faster reduced-precision modes;
3. a source-independent virtual FP64 ISA;
4. compiler-managed precision selection.

This audit asks whether a public project or paper found in the searched sources
already exposes that complete combination. It also identifies narrower claims
that prior work already occupies.

## Method and limits

The review searched GitHub repository metadata and README text for combinations
of `Metal`, `Apple GPU`, `float64`, `binary64`, `double precision`, `softfloat`,
and `virtual FP64`. It queried OpenAlex for Apple-GPU FP64 emulation, Metal
double-precision emulation, software binary64 GPU virtual ISAs, and
compiler-managed mixed precision. Candidate projects were then inspected at a
named commit or release using their own source, tests, and documentation.

The first ten OpenAlex results for each query contained no work whose title or
metadata described the complete four-part stack. General Bing results were too
noisy to use as technical evidence, including tokenizing `Metal64` as unrelated
consumer hardware. Search-engine absence is not proof of absence, private work
is invisible, and repository documentation is an author claim until reproduced.

## Claim consequences

The review rules out these claims for VF64Metal:

- first software binary64 arithmetic on Apple GPUs;
- first correctly rounded binary64 core on Apple GPUs;
- first complete general-purpose software binary64 runtime;
- first compiler path that lowers source `double` to software operations on
  Apple GPUs.

No inspected source combined VF64Metal's three frozen precision modes,
source-independent bytecode ISA, explicit compiler policies, automatic
per-region precision selection, and scientific-workload evidence. That is a
useful differentiation, but a bounded search cannot prove the word “first.”

The publication-safe 1.0 statement is therefore descriptive:

> **A complete virtual FP64 architecture for Apple GPUs: correctly rounded
> IEEE-754 binary64, faster reduced-precision modes, a virtual FP64 ISA, and
> compiler-managed precision selection.**

Any future “first” wording requires an independent literature and implementation
review immediately before publication, with its scope and date attached. Until
then, the repository must not imply novelty for the exact runtime or compiler
lowering separately.

## Reproducibility notes

- GitHub creation and commit dates were read from the public repository API.
- The `soft-fp` comparison uses its tagged `v2.0.1` source, not the moving
  default branch.
- The AdaptiveCpp comparison uses the documented `fork-safe-metal` branch
  revision. The backend calls itself experimental, and this audit did not build
  or independently execute it.
- Reported upstream TestFloat counts and performance are not VF64Metal
  measurements.
